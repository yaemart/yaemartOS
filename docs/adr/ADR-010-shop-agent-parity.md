# ADR-010: Shop Domain Agent-Native Parity

**Date:** 2026-05-02  
**Status:** Accepted  
**Deciders:** David Gao  
**Context:** W7 ShopBinding Management Page completion

---

## Context

The `/shops` management page allows administrators to:

1. View all shops for their brand (with platform and market names)
2. View Lingxing shops available for binding
3. Bind an internal shop to a Lingxing shop
4. Toggle data sync on/off for a bound shop
5. Soft-unbind a shop (clear `lingxingShopId`, disable sync, preserve history)

Per AGENTS.md, any operation a user can perform in the UI must be achievable by an Agent through documented REST endpoints (Agent-Native Parity principle).

---

## Decision

### Human Confirmation Gates (UI Layer Only)

Write operations require human confirmation **in the UI layer only**. Agent calls via authenticated JWT are treated as administrator operations and do not require a separate draft/approval workflow.

This differs from AI-generated content (e.g., Listing generation) which uses a `draft → activate` pattern because:

- Shop bindings are administrative configuration, not user-visible content
- The binding decisions are explicitly made by an operator, not autonomously generated by AI
- Adding a draft layer would create unnecessary latency for legitimate admin operations

### Soft-Unbind vs Hard-Delete

Unbinding sets `lingxingShopId = null` and `syncEnabled = false` on the existing `ShopBinding` row rather than deleting it. This preserves audit history and allows re-binding without losing metadata.

## Agent Capability Map

| UI Operation       | Agent Function         | HTTP Method & Path                                                 |
| ------------------ | ---------------------- | ------------------------------------------------------------------ |
| 查看店铺列表       | `listShops()`          | `GET /shops` (header: `x-yaemart-brand`)                           |
| 查看单个店铺       | `getShop(id)`          | `GET /shops/:id`                                                   |
| 查看领星可绑定列表 | `listLingxingShops()`  | `GET /shops/lingxing-available`                                    |
| 绑定店铺           | `bindShop(id, dto)`    | `POST /shops/:id/bind` — body: `{ lingxingShopId, bindingToken? }` |
| 切换同步           | `toggleSync(id, bool)` | `PATCH /shops/:id/binding` — body: `{ syncEnabled: boolean }`      |
| 解绑店铺           | `unbindShop(id)`       | `PATCH /shops/:id/binding` — body: `{ unbind: true }`              |

All endpoints require:

- `Authorization: Bearer <JWT>` (valid admin token)
- `x-yaemart-brand: <brandId>` header for brand-scoped operations
- IAM policy: `shops:read` for GET, `shops:write` for POST/PATCH

## Consequences

- **Positive:** Full Agent-Native parity — any UI action is reachable via REST
- **Positive:** No draft mechanism means lower latency for admin operations
- **Positive:** Soft-unbind preserves audit history; re-binding is straightforward
- **Neutral:** Human confirmation gates in UI only — Agent is trusted to act autonomously when authenticated
- **Risk:** If Agent credentials are compromised, write operations can be performed without UI confirmation; mitigated by JWT expiry and Casbin RBAC (`shops:write` policy)
